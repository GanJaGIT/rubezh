# Баланс карт: $ARGUMENTS

Правила — §2.6, §2.7, §3.9, §3.10 `docs/TZ.md`. Числа меняются только в `src/content/*.json`.

1. **Исходная точка.** Запусти `npm run balance` и прочитай `docs/balance.md`. Запиши текущие показатели BAL-01: доля боёв с короной, с падением крепости, средняя длительность, доли побед всех карт.
2. **Диагноз.** Для карты `$ARGUMENTS` (или для каждой карты вне коридора 0,44–0,56):
   - сравни её долю побед с соседями по стоимости;
   - посмотри, как часто бот её играет и накладывает (если бот почти не играет карту, сначала проверь оценку в `src/sim/bot.ts`, а не числа карты);
   - через `npm run sim -- --deck0 … --deck1 … --seeds 50` сыграй колоду с картой против той же колоды с заменой карты на соседнюю по стоимости.
3. **Одна правка за раз.** Меняй одно число на 10–20%: прочность, урон, перезарядку, радиус или стоимость. Стоимость в порохе — грубый рычаг, трогай последней. После правки — снова `npm run balance`.
4. **Не сломай бой.** После каждой правки проверь общие коридоры BAL-01: корона хотя бы одна ≥ 70%, крепость пала в 10–30%, длительность 150–220 с. Прочность башен и крепости (GD-12) — главный рычаг против позиционного тупика: прототип показал, что при 1400/2400 почти половина боёв заканчивалась без корон.
5. **Прокачка.** Если правка затронула рост с уровнем — прогони BAL-03 (колоды на 2 уровня выше побеждают в 65–80%).
6. **Журнал.** Запиши в PROGRESS.md → «Решения»: карта, что было → что стало, показатели до и после. Если правка меняет описание карты — обнови тексты в i18n.
7. **Тесты.** `npm run test` (T-04…T-09 и T-11 не должны ломаться от чисел — если ломаются, тест завязан на конкретные числа, перепиши его через данные из JSON).
