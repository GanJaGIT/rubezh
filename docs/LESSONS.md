# Уроки двух игр

Опыт «Сладкого конвейера» (фабрика-головоломка) и «Сплава» (merge на реке) — обе прошли путь от идеи до релизного пакета для Яндекс Игр с Claude Code. Каждая строка: **что случилось → как правильно → где это уже сделано в шаблоне**. Claude читает этот файл в начале каждого этапа; новая игра добавляет сюда свои уроки в конце.

## 1. Платформа и SDK

- **`GameplayAPI.start()` уходил раньше `LoadingAPI.ready()`** (под прокси). → Ничего из разметки геймплея до `ready()`. → `GameplayState.setReady()`, вызывается только из колбэка первого кадра (`src/main.ts`).
- **`ready()` нужно звать ровно один раз, когда первый экран интерактивен**, и экрана загрузки в этот момент уже не должно быть. → `LoadingScreen.done()` перед `platform.gameReady()`; тест архитектуры: `.gameReady(` только в `main.ts`; смоук — ровно один вызов.
- **Пустые пары `start()`/`stop()`**, когда окно закрылось и тут же открылось другое (или реклама одним нажатием). → `stop()` сразу, `start()` в конце задачи (микрозадача) и только если игра всё ещё идёт. → `src/services/gameplay-state.ts`.
- **После `game_api_resume` платформа сама шлёт `start()`**, а у нас открыта «Пауза». → Отправить `stop()` ещё раз (`reassert`). → `Lifecycle.attach`.
- **Пауза SDK, пришедшая до создания `App`** (во время облачной загрузки), терялась. → Подписывайтесь на события платформы как можно раньше; в шаблоне это допустимо, пока уровень с ожиданием первого действия.
- **В моке `sdk-dev-proxy` нет событий выбора аккаунта** — подписка падала. → Подписываться, только если событие есть в SDK. → `YandexPlatform`.
- **После диалога выбора аккаунта** облачная копия должна заменить прогресс целиком, без «свежая по `updatedAt`». → `SaveService.reloadFromCloud()`.
- **`sdk-dev-proxy` открывает вкладку в браузере пользователя** и работает по HTTPS с самоподписанным сертификатом; антивирус ругается, встроенный браузер Claude его не открывает. → `npm run check:yg`: Chromium без окна, сертификат разрешён только ему, `scripts/no-browser-tab.cjs` гасит открытие вкладки.
- **`/sdk.js` в dev даёт 404 в консоли** → строгий смоук падает. → Плагин Vite отдаёт пустую заглушку в `dev` и `preview` (`vite.config.ts`).
- **В релиз не должна попасть `LocalPlatform`** с заглушками рекламы (это «имитация рекламы», п. 1.16). → `createPlatform()` берёт `LocalPlatform` только при `__DEV_HOOKS__`; `check:build` ищет маркеры заглушек.
- **Лидерборд**: топ-100 SDK не даёт — `getEntries` отдаёт до 20 лучших и до 10 вокруг игрока; лимит 20 запросов за 5 минут; `setScore` — не чаще раза в секунду и только для вошедших. → `LeaderboardService` (очередь, кеш 60 с); окно показывает топ-7 и строку игрока (без прокрутки на телефоне).
- **Ежедневный рейтинг в одной доске**: день в счёт (`день × 100000 + очки`), показывать только сегодняшние строки. День — по `serverTime()` и по Москве (`src/services/day.ts`), иначе перевод часов даёт лишние награды.
- **Покупки**: постоянная покупка не консумируется — её эффект берётся у платформы при каждом запуске, подарок — один раз (отметка в `seen`); расходуемая — начислить → сохранить в облако сразу → `consumePurchase`. Необработанные покупки — при каждом запуске (1.13.1). Цена и значок валюты — из SDK. Пока товаров нет в консоли, флаг `features.iap = false`, и **активных товаров в консоли быть не должно** (1.13.6). → `ShopService`, UPLOAD.md.
- **Описание товара в консоли** пишет владелец — напоминать ему о запретах (см. §10, «радуга»).

## 2. Пауза, фокус, реклама — самое коварное

- **Река (уровень) не должна идти, когда игрок не смотрит**: скрытая вкладка, `blur`, `pagehide`, пауза SDK, реклама — всё ставит «Паузу» и тишину. → `Lifecycle` + `AudioService` (множество причин тишины).
- **Игрок ушёл ВО ВРЕМЯ рекламы** (свернул вкладку, фокус остался в странице платформы после крестика) — после ролика уровень ехал сам при остановленном `GameplayAPI` и выключенном звуке. Нашёл модератор второй игры. → После любой рекламы: если осталась причина «не здесь» — открыть «Паузу», а не продолжать. → `App.away()`, `afterComplete`, `continueForAd`; e2e `interruptions.spec.ts`.
- **Полноэкранный режим по первому касанию растит окно под пальцем** → обработчик ресайза открывал «Паузу» посреди первого перетаскивания в обучении. → Рост окна в первые 1,5 с после первого касания (та же ширина) и `fullscreenchange` — не уход. → `App.stageResized`.
- **Два ролика подряд**: досмотрел «Удвоить монеты» → «Дальше» → ещё и полноэкранная. → После досмотренного видео в этом окне полноэкранную не показывать. → `afterComplete(go, watchedVideo)`.
- **Полноэкранная реклама** — только сразу после «Дальше»/«В меню», с N-го уровня, не чаще 180 с по **серверным** часам, время — в сохранении (перезагрузка не обнуляет). Никогда по таймеру и посреди уровня. → `AdService`; тест архитектуры ищет таймеры рядом с вызовом.
- **Rewarded** — только по кнопке, на которой видно и значок видео, и слово «реклама» («Удвоить монеты за рекламу»); награда — в `onRewarded`; без досмотра — ничего; награда — бонус, игра проходится без неё (боты играют без бустеров).
- **Стики-баннер** только между уровнями; в консоли включить «Использовать API для показа sticky-баннера», иначе он висит и в уровне.
- **Звук Phaser** создаёт AudioContext при загрузке, до касания — Firefox предупреждает. → `audio: { noAudio: true }`, звук только у `AudioService`, после первого касания.
- **Встроенный браузер Claude, пока панель не в фокусе, сообщает `visibilityState = hidden`** → игра честно стоит на паузе. Это не баг; проверять в Playwright.

## 3. Сохранения

- Локально — сразу после каждого изменения; в облако важное — сразу (`flush`), остальное — пакетом раз в 10 с и при уходе со вкладки; не больше 80 записей за 5 минут (лимит SDK — 100). Без авторизации. → `SaveService`.
- **Битое/частичное сохранение не должно ломать игру** → `migrate()` читает любые данные в текущую схему; тест на худший размер (< 50 КБ).
- **Половина награды за проигрыш** (если есть) — начислять и сохранять сразу при проигрыше, а не при закрытии окна: игрок может закрыть игру из окна.
- **Ключ `localStorage`** — по имени игры (`__APP_ID__`): на `localhost` все проекты делят одно хранилище.
- Большие раскладки (песочницы) — компактной строкой, с ограничением частоты записи.

## 4. Вёрстка и интерфейс

- **Кнопка 44 px в шапке высотой 44 px вылезала на 2 px**: нижняя «кромка» шапки была `border`. → Кромки — `box-shadow inset`. → `styles.css`.
- **На низком экране (360×560) кнопка «Готово» уходила за край окна настроек** → компактный режим окон `@media (max-height: 640px)`; окна выше экрана прокручиваются пальцем (`touch-action: pan-y`, `touchmove` не гасится внутри окна). → `styles.css`, `stage.ts`.
- **Всплывающее сообщение закрывало заголовок окна** → сообщения ждут, пока окно закрыто (`Toast` с очередью).
- **WebKit теряет клик**, если узел под пальцем переписывается между нажатием и отпусканием (иконка, текст каждый кадр). → Писать в DOM только при изменении (`setText`), `button svg, img { pointer-events: none }`.
- **Анимированная тень (`box-shadow`) перерисовывала страницу каждый кадр** — тест 2560×1080 шёл 3 минуты. → Анимировать только `transform`/`opacity`, ставить на паузу под окном.
- **`display: none` у экрана с холстом** → Phaser запоминал 0×0 и холст пропадал. → Прятать через `hidden` у хоста и усыплять цикл; обработчик размера игнорирует 0×0; первый `fit()` всегда сообщает размер.
- **Холст в CSS-пикселях мылится на телефоне** → холст в физических пикселях (DPR до 3), `setZoom(1/dpr)`, камера `zoom = dpr`, мир в CSS-пикселях (`createGame.ts`).
- **Активная область 2:1 только на компьютере**; телефон — весь экран, иначе на вытянутых экранах поля по бокам.
- **Клетка ≥ 44 px на самом большом уровне на 360×560** — проверяется тестом; если не влезает — уменьшать поле, а не клетку (требование «без прокрутки» важнее).
- **Ландшафт телефона** не поддерживаем — ориентация портретная в консоли.
- **Подсказка «нажми сюда» прыгала** (`translate` вверх-вниз) — игрок промахивался по кнопке. → Выделять цветом и лёгким масштабом на месте, кнопка не сдвигается (`.menu-level.next` в `styles.css`).
- **Турецкий (и другие языки с ğ ş ı İ)** рисовался системным шрифтом вперемешку с Nunito. → Подключить подмножество `latin-ext` шрифта вместе с новым языком.
- **Кириллица в TS-комментариях** («п. 4.4») роняет тест архитектуры. Пишите «req. 4.4».
- Окна — свои (`Modals`), никогда `alert/confirm/prompt`.

## 5. Ввод

- Pointer Events DOM на элементе поля, ввод Phaser выключен: касание, мышь и перо — один путь; интерфейс над полем не «пробивает».
- Клавиатура — только `event.code` (работает при русской раскладке), без перехвата `Ctrl/Alt/Meta` сочетаний, повтор зажатой клавиши игнорируется.
- Двойное касание бустера/кнопки в пределах тика — одно действие; видео не запускается второй раз, пока первое ждёт.
- Протягивание: смещать предмет вверх на ~28 px только для пальца (палец закрывает предмет), мышью — под курсором.
- Нет контекстного меню, выделения, прокрутки, масштабирования (`index.html` + `installInputGuards`).

## 6. Звук

- Синтез в браузере (Web Audio) вместо mp3: 0 КБ до `ready()`, без декодирования. Маримба + колокольчик + шум через фильтр + свёрточное «эхо» звучат прилично; простые синусы — «пищалки».
- Высота «удачного хода» — по мажорной пентатонике (`scalePitch`), не по хроматике.
- Не больше 6 звуков в секунду.
- Тихий фон — включает `GameplayState` (то же условие, что `GameplayAPI.start`).
- Музыка — только CC0, её выбирает владелец; без неё игра считается законченной.

## 7. Графика

- **SVG → атлас** (`npm run art`, `@resvg/resvg-js`, детерминированно, без браузера); клетка атласа 160 px (на телефоне DPR 3 клетка ~150 px). Атлас в `src/assets` (имя с хешем — кеш не мешает обновлениям).
- **Младшие предметы рисуются меньше в кадре** → значок уровня висел далеко от картинки. → При сборке атласа меряется видимая часть каждого кадра (`atlas-bounds.json`); по ней подгоняется размер и ставится значок.
- **Значок уровня не исчезал** после слияния: удаляли спрайт, но не значок. → Любой составной объект удаляется одной функцией.
- **У нового спрайта во время появления масштаб 1** → значок рисовался огромным. → Масштаб задавать сразу при создании.
- **Цветные градиенты в SVG иконок DOM** конфликтуют по `id`, если иконка встречается дважды. → Иконки без `id` и градиентов (`art/ui`), сложные картинки — через `<img src>`.
- Стиль фиксируется в `docs/art-style.md` до рисования; контактные листы (`test-results/art/`) — смотреть глазами.
- Прежде чем рисовать много, нарисовать 2 концепта ключевого экрана и выбрать.

## 8. Сборка и архив

- `index.html` в корне архива; имена `a–z 0–9 . _ -` (Vite по умолчанию даёт заглавные в хешах → `hashCharacters: 'hex'`, имена в нижнем регистре); без `.map`, без `purchases-catalog.json`, без `.gitkeep`.
- **Phaser держит строку `https://phaser.io`** → плагин вырезает её, в архиве нет ни одного внешнего адреса.
- **Firefox предупреждает** «Alpha-premult and y-flip are deprecated» из-за служебной текстуры Phaser → плагин `patch-phaser-typed-uploads` (сборка падает, если шаблон не найден после обновления Phaser).
- **MIT (Phaser) и OFL (шрифт)** требуют приложить лицензию к копиям, а минификация вырезает `@license` → `public/licenses.txt` в архиве (без внешних ссылок).
- **TypeScript 6.0.x**, не 7: `typescript-eslint` 8.71 поддерживает < 6.1. Все версии точные.
- **npm 11 не запускает install-скрипты пакетов** → бинарник `ffmpeg-static` бывает недокачан («Exec format error») → `node node_modules/ffmpeg-static/install.js`; `npm run doctor` это проверяет.
- Медленная сеть: `npm install --prefer-offline --maxsockets=3`.

## 9. Тесты и проверка

- **Браузеры Playwright в `~/.cache/ms-playwright`** (`scripts/browsers-path.ts`), а не в `%LOCALAPPDATA%`: внутри упакованного приложения Claude Windows перенаправляет AppData, и Firefox не стартует («side-by-side configuration is incorrect»).
- **Chromium с `--use-angle=swiftshader`**, иначе браузер сам пишет «GPU stall due to ReadPixels» и строгий смоук (любое предупреждение — провал) падает.
- **3 воркера, без трассировки**: WebGL в тестах программный, больше — процессор захлёбывается и клики ждут по 30 с.
- **Ожидания после рекламы-заглушки — 15 с**, а не 5: под нагрузкой переход длится дольше.
- **Замер загрузки (PERF-02) параллельно с другими тестами показывал 21 с вместо 3** → отдельный проект Playwright `perf`, который идёт последним и один.
- **Компьютер уснул посреди прогона** → тесты висели 5 часов (`ERR_NETWORK_IO_SUSPENDED`). → Перед длинным прогоном просить приложение не засыпать (keep-awake).
- **Порты 4190 и подобные браузеры блокируют** (WebKit не открывает, Firefox сбоит) — берите 4174–4185, 5173.
- **Скриншоты QA-04 — JPEG** (PNG 2560×1080 кодируется секундами), лимит теста вёрстки — 180 с.
- `npm run verify` — единственный критерий «готово». Не говорить «готово», не показав зелёный вывод.
- После исправления — один прогон проверки; не гонять одно и то же повторно без изменений.

## 10. Содержание и модерация

- **Никакой радуги и радужных мотивов** (ассоциация с ЛГБТ запрещена в РФ): ни в графике, ни в названиях («Радужная капля» → «Волшебная капля»), ни в описаниях товаров в консоли, ни в промо.
- Запрещены: политика, война, религия, чёрная магия, реалистичное насилие, предсказания здоровья, реальные призы, внешние ссылки, интерактивный ИИ (п. 3.4, 3.7, 8.4, 1.23).
- Тексты вычитывать на обоих языках; названия уровней ≤ ~22 символов.
- «Как играть» должно описывать управление и на телефоне, и на компьютере — и все ключевые приёмы (во второй игре забыли «берег»).
- **Название одинаковое в игре, на обложке, в конце видео и в черновике каждого языка** (п. 5.1.3) — у английской страницы свои материалы с английским названием. Это был единственный блокер модератора во второй игре.
- Уникальность названия проверить в каталоге до релиза (поиск `yandex.ru/games/search?query=…`).

## 11. Промо-материалы

- **Иконка и обложки — композиции из спрайтов игры, не скриншоты**, без рамок и скруглений; иконка без текста (одна на все языки).
- **Запись видео Playwright** даёт низкий битрейт, отстаёт от реального времени (хвост теряется при закрытии), а при окне меньше кадра кладёт картинку в угол, остальное серое. → **Покадровая съёмка**: цикл Phaser спит, `game.step()` по 1/30 с, кадр — `Page.captureScreenshot` с явным `scale`, CSS-анимации замедляются под темп; титр — отдельная картинка с проявлением; ffmpeg. → `scripts/promo.ts`; проверка «четверть кадра серая» — ошибка.
- **Видео «до 28 с»**: 28,03 — уже нарушение. Держать ≤ 27,8 с.
- **Геймплей ≥ 70% времени видео** — меню/деревня может не засчитаться; уровень ≥ 20 с из 27.
- На скриншотах — только уровни; уведомления скрыть; кадр — сразу после удачного хода (эффект в кадре).
- Тексты черновика — в `docs/store.json` (в git), `npm run draft` считает символы (и с CRLF!), ищет запретные слова («бесплатно», «лучший», «free», «top»…), повторы между полями, сверяет название с `game.title`.

## 12. Процесс работы с Claude

- По этапам ТЗ, маленькими шагами: изменение → тест → коммит с ID требования.
- Решения без владельца — в PROGRESS.md «Решения»; вопросы — в «Вопросы владельцу», работа не останавливается.
- **Агенты (модератор, параллельные художники) обрываются на сетевых ошибках API** — давать им писать находки в файл по ходу; если оборвался — запускать заново с этим файлом.
- **Пакетные правки через `node -e` / heredoc ломают обратные кавычки и `\n`** в шаблонных строках TS. → Для кода с обратными кавычками — Write/Edit или .cjs-скрипт в scratchpad, и проверять результат.
- Игровую графику от агентов-художников проверять контактными листами; давать им руководство по стилю.
- Плейтест владельца после этапов 2, 3 и 5 — что смотреть, писать в START.md.
- Публикация на GitHub — по образцу (README с баннером, гифкой, скриншотами, управлением, командами, устройством; релиз с архивом и видео). Перед пушем — проверка истории на секреты.

## 13. Баланс уровней

- Уровни проверяются **тремя ботами с человеческим темпом** на 20 сидах; у бота **разброс реакции** (иначе бот или никогда не ошибается, или всегда проигрывает — нет кривой сложности).
- Нормы (подстроить под игру): обычный бот выигрывает 20/20, новичок — не меньше 12/20, средняя победа обычного — в заданном диапазоне секунд; поток предметов/событий ограничен по главам.
- Ошибки каскадом: стоит новичку отстать — проигрыш почти гарантирован; поднимать «запас» (время жизни, жизни) постепенно.
- Экономика: `npm run balance` (сколько заработает обычный бот к каждой покупке); цены — в JSON.
- Темп живого игрока снять на плейтесте (`?dev=1`, «actions/s») и подстроить ботов.

## 14. «Рубеж»

- **Высокие спрайты (постройка выше своей клетки) налезали на соседний ряд атласа**: раскладка атласа считала все кадры квадратными. → Высота ряда — по самому высокому кадру. → `scripts/art.ts`.
- **Длинный список в окне на 360×560 выталкивал «Закрыть» за край экрана.** → Ряд кнопок окна прилипает к низу (`position: sticky`), список прокручивается под ним; тест вёрстки не считает это пересечением. → `styles.css`, `layout.spec.ts`.
- **Heredoc в Bash ломается на кавычках внутри TS** — файлы с кодом писать через Write.
- **Турнир ботов врёт, если бот не играет часть карт.** Бот прототипа никогда не копил порох и почти не ставил карты за 5–7 — баланс выглядел хорошим, а с копящим ботом крепость падала в 90% боёв. → Перед подбором чисел смотреть, сколько раз за бой бот играет каждую карту; если карту почти не играют — сначала чинить оценку бота. → `src/sim/bot.ts` (SAVE_MARGIN).
- **Покрытие (v8) замедляет тяжёлые тесты в ~5 раз**: 1000 боёв — 40 с без него и ~200 с с ним. → Тяжёлые тесты — в отдельных файлах (vitest гоняет файлы параллельно) и с честными тайм-аутами.
- **Фоновый `npm run verify > log; tail log` всегда завершается с кодом 0** — код выхода берётся у `tail`. Так красный verify ушёл в коммит и на GitHub. → Писать `echo VERIFY_EXIT=$?` сразу после verify и смотреть итоговую строку `verify: GREEN/RED`, а не код фоновой задачи.
- **Кириллица в комментарии `.ts` (даже цитата текста интерфейса) роняет тест архитектуры** — в комментариях описывать по-английски.
