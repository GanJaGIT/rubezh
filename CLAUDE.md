# «Рубеж» — правила проекта

Соревновательная дуэль фортов для Яндекс Игр: колода карт-построек, постройки ставятся на клетки поля 7×10 и стреляют сами, зона застройки ползёт к врагу, одинаковые карты накладываются в звёзды. Соперники — записи боёв других игроков через асинхронный мультиплеер Яндекса, пока их мало — боты. Полное ТЗ — `docs/TZ.md`, журнал — `docs/PROGRESS.md`. С владельцем (Артемий) общайся по-русски.

## Как работать

1. В начале каждой сессии прочитай `docs/PROGRESS.md` и разделы ТЗ для текущего этапа (таблица ниже).
2. Делай только текущий этап. Следующий — по команде владельца.
3. Маленькие шаги: изменение → тест → коммит. Сообщение коммита начинается с ID требования: `SIM-13: урон применяется одновременно`.
4. Проверяй себя сам: тесты, запуск в браузере через Playwright, скриншоты (смотри их). Не говори «готово», пока `npm run verify` не зелёный.
5. Неясно — выбери самый простой вариант, не нарушающий требований Яндекса, и запиши решение в PROGRESS.md → «Решения». Нужен владелец — PROGRESS.md → «Вопросы владельцу», и продолжай остальную работу.
6. В конце сессии обнови PROGRESS.md: что сделано (с ID), что дальше, проблемы.

## Архитектура — не нарушать

- `src/sim` и `src/meta` — чистый TypeScript: без Phaser, DOM, `window`, `Date`, `Math.random`. Дробные величины — целые тысячные (SIM-04). Урон в тике применяется одновременно (SIM-13). Детерминизм и инварианты — SIM-40, SIM-41.
- Бой меняется только действиями `play` (§3.4) — от игрока, бота и воспроизведения записи одинаково.
- Записи соперников: `isEventBased: false`, таймлайн читает игра сама (YG-22); запись проверяется до боя (REP-01); недопустимые клетки — по REP-04.
- `src/platform` — единственное место, где есть `YaGames` и `ysdk`.
- Тексты — только `src/i18n/*.json`. Контент (карты, башни, арены, прокачка, сундуки, задания, колоды ботов) — только JSON в `src/content/`.
- Поле боя рисует Phaser 4, меню и интерфейс — DOM и CSS.
- `GameplayState` — единственный, кто вызывает `GameplayAPI.start()` и `stop()`. `AudioService` — единственный, кто включает звук.

## Правила, которые легко нарушить

- Бой и воспроизведение записи стоят, когда игрок не смотрит: пауза, скрытая вкладка, `blur`, реклама, ресайз (SIM-03, YG-04, YG-05).
- Время сундуков, заданий и магазина — только `serverTime()` (YG-25).
- Полноэкранная реклама — только после боя по кнопке «В меню», с 3-го боя, не чаще раза в 180 секунд. Никогда в бою и при поиске соперника.
- Rewarded — только по кнопке с понятной наградой, награда в `onRewarded`. Баннер — только в меню.
- Честность: в бою видно, запись это или бот; в описании игры сказано, что соперники — записи и боты.
- Баланс карт меняется только через JSON и подтверждается турниром ботов (`npm run balance`, BAL-01).
- Клавиатура — только `event.code`. Нет контекстного меню, выделения, прокрутки, `alert`/`confirm`.
- Прогресс сохраняется сразу после изменения и без авторизации.
- Пути относительные; в архиве `index.html` в корне; имена латиницей. Никаких внешних запросов, сторонней рекламы, интерактивного ИИ.

## Команды

Создаются на Этапе 0: `npm run dev`, `dev:yg`, `test`, `e2e`, `verify`, `sim`, `balance`, `economy`, `bench`, `spike`, `art`, `build`, `zip`, `promo`.

## Документация и прототип

- Яндекс Игры: https://yandex.ru/dev/games/doc/ru/llms.txt — перед работой с SDK читай нужную страницу. Асинхронный мультиплеер — https://yandex.ru/dev/games/doc/ru/sdk/sdk-multiplayer-sessions.md.
- Phaser 4: официальные skills в `.claude/skills/` (копируются на Этапе 0).
- `docs/prototype/` — прототип боя и проверки записей на Python. Иллюстрация, а не источник истины.

## Навыки и агенты

- `/card-balance [карта или «всё»]` — проверить и подстроить баланс карт турниром ботов.
- `/yg-audit` — проверка по требованиям Яндекса (с Этапа 4).
- `/yg-release` — релизный пакет (Этап 5).
- Агент `yg-moderator` — независимая проверка перед модерацией.
