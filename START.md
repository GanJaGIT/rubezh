# Как вести «Рубеж» через Claude Code

Инструкция для владельца. Claude Code эту инструкцию не исполняет — ему хватает `CLAUDE.md` и `docs/TZ.md`.

Концепция игры (для себя): https://claude.ai/artifact/Q1tiXVM4WMx8YeuASBQsfk

## Что в комплекте

| Файл | Зачем |
|---|---|
| `docs/TZ.md` | Техническое задание: правила боя, 16 карт с числами, симуляция, запись и воспроизведение соперников, бот, прокачка и сундуки, интерфейс, требования Яндекса, этапы с критериями приёмки |
| `CLAUDE.md` | Правила проекта. Claude Code читает его автоматически в каждой сессии |
| `docs/PROGRESS.md` | Журнал Claude: что сделано, какие решения принял, вопросы к тебе, результаты пробника мультиплеера |
| `docs/prototype/` | Прототип боя на Python, на котором проверялись числа (`proto.py`) и воспроизведение записей (`replay_check.py`) |
| `.claude/settings.json` | Разрешает npm-скрипты, тесты и git без вопросов; `git push` — только с подтверждением |
| `.claude/skills/` | Команды `/card-balance`, `/yg-audit`, `/yg-release` |
| `.claude/agents/yg-moderator.md` | Независимая проверка «глазами модератора» перед отправкой |

## Один раз перед стартом

1. Установи Node.js LTS (nodejs.org) и Git (git-scm.com). Проверка в терминале: `node -v` и `git -v`.
2. Распакуй архив `Rubezh.zip` на рабочий стол: правый клик → «Извлечь всё…» → выбери рабочий стол. Получится папка `Rubezh`. Внутри есть служебная папка `.claude` — в Проводнике она может быть не видна, это нормально.
3. Открой папку в Claude Code: в приложении Claude выбери папку `Rubezh` на рабочем столе, или в терминале `cd Desktop\Rubezh`, затем `claude`.
4. Чтобы Claude реже спрашивал разрешения, включи режим автоматического принятия правок (`acceptEdits`) или `auto`, если он доступен.

## Важное отличие от прошлых игр: сначала пробник

Соперники в «Рубеже» — записи боёв других игроков через асинхронный мультиплеер Яндекса. В документации не сказано несколько важных вещей: нужна ли авторизация, видишь ли ты свои записи, как быстро они появляются. Поэтому на Этапе 0 Claude соберёт маленький пробник, а ты проверишь его на настоящей платформе. Это 15 минут твоего времени, и они могут сэкономить недели.

**Как проверить пробник (после Этапа 0):**

1. В консоли Яндекс Игр создай отдельный черновик, например «Рубеж — пробник».
2. Загрузи архив `release/spike-<дата>.zip`.
3. Открой черновик под своим аккаунтом, введи число 500 и нажми «Записать». Дождись надписи об успехе.
4. Нажми «Загрузить» — посмотри, видна ли твоя же запись.
5. Открой черновик в другом браузере или в режиме инкогнито: сначала без входа, потом под другим аккаунтом Яндекса (можно попросить друга). Нажми «Загрузить».
6. Повтори «Загрузить» через 5 и через 30 минут, если запись не появилась сразу.
7. Сделай скриншоты экрана после каждого шага и перешли их Claude с промптом «Вот результаты пробника мультиплеера, заполни ST-02 в PROGRESS.md и уточни требования».

## Промпты по этапам

Отправляй один промпт на этап и дожидайся конца этапа.

**Этап 0 — каркас и пробник**

```
Прочитай CLAUDE.md, docs/TZ.md и docs/PROGRESS.md. Выполни Этап 0 из ТЗ полностью, включая пробник мультиплеера ST-01, и не начинай Этап 1. В конце покажи вывод npm run verify, путь к архиву пробника и обнови docs/PROGRESS.md.
```

**Этапы 1–5** — тот же текст с другим номером:

```
Выполни Этап 1 из docs/TZ.md полностью и не начинай следующий. В конце покажи вывод npm run verify и обнови docs/PROGRESS.md.
```

**Режим «работай, пока не закончишь»:**

```
/goal Этап 1 из docs/TZ.md выполнен: все его критерии приёмки выполнены, npm run verify завершился без ошибок и его вывод показан в чате, docs/PROGRESS.md обновлён, Этап 2 не начат. Остановись после 80 ходов.
```

**Плейтест**

```
Я сыграл 5 боёв. Замечания:
- …
- …
Исправь, прогони npm run verify и обнови PROGRESS.md.
```

**Если карта слишком сильная или бесполезная**

```
/card-balance mortar
Мортира слишком сильная: соперник ставит две за линией, и башня падает за 20 секунд.
```

**Релиз**

```
/yg-release
```

Затем:

```
Попроси агента yg-moderator проверить сборку и release/. Исправь блокеры и риски, потом снова запусти /yg-release.
```

## Что проверить самому после этапа

| Этап | Что сделать | На что смотреть |
|---|---|---|
| 0 | `npm run dev`; проверить пробник по инструкции выше | Поле 7×10 с крепостями; пробник записывает и загружает |
| 1 | Прочитать PROGRESS.md и `docs/balance.md` | Тесты зелёные; бои ботов в коридорах: короны ≥ 70%, бой ~3 минуты, карты 0,44–0,56 |
| 2 | Сыграть 5 боёв против бота на компьютере и телефоне (`npm run dev -- --host`, телефон в той же Wi-Fi сети) | Карты удобно тянуть, видно, куда можно ставить, понятно, кто в кого стреляет; хочется сыграть ещё |
| 3 | Поиграть 30–40 минут: сундуки, прокачка, колоды | Награды радуют, прокачка ощутима, вторая арена открывается в первый день |
| 4 | Загрузить черновик, сыграть бой с одного аккаунта и найти свою запись соперником с другого | Соперник-запись ставит постройки «как живой», подпись «Запись боя» видна |
| 5 | Посмотреть всё в `release/` | Картинки красивые, тексты без ошибок, видео живое |

Главные вопросы на плейтестах: бывает ли, что бой «встал» и никто не может пробиться, и есть ли карта, без которой нельзя победить. Если да — это задача для `/card-balance`.

## Твоя часть в консоли Яндекс Игр

До Этапа 4:

- создать черновик игры «Рубеж», чтобы получить ID (пробник — в отдельном черновике);
- в разделе «Реклама» включить стики-баннеры (телефон — внизу, компьютер — включить) и опцию «Использовать API для показа sticky-баннера»;
- включить автоматический полноэкранный режим, если такая настройка есть;
- создать лидерборд `trophies` (числовой, по убыванию).

Если договор позволяет покупки (для этой игры они особенно важны):

- добавить товары: `gems_80`, `gems_500`, `gems_1200` (кристаллы, расходуемые), `starter_pack` (стартовый набор, расходуемый), `no_ads` («Без рекламы», постоянный);
- добавить свой логин в «Список логинов для тестовых покупок»;
- сказать Claude включить `features.iap` в `src/config.ts`.

Перед отправкой на модерацию — шаги из `release/UPLOAD.md`.

## Если что-то пошло не так

- `npm run verify` красный, и Claude не справляется за 2–3 попытки: «Остановись. Опиши проблему в PROGRESS.md и предложи два варианта решения».
- Claude сломал то, что работало: «Откати изменения к последнему коммиту, где verify был зелёным».
- Пробник показал, что мультиплеер работает не так, как ожидалось: перешли результаты Claude — он предложит, как поменять подбор соперников, а в худшем случае игра будет работать на ботах, пока вопрос не решится.
- Модерация отказала: перешли Claude текст отказа и картинку: «Вот отказ модерации. Исправь, прогони /yg-audit и /yg-release».

## Сроки

Этапы 0–5 — примерно 6–8 недель, если работать вечерами. Это заметно больше, чем «Сплав»: здесь бой в реальном времени, бот, записи соперников и полноценная мета с прокачкой. Если время поджимает, Claude может выпустить версию с аренами 1–3 и 10 картами, а остальное добавить обновлением (§11 ТЗ).
